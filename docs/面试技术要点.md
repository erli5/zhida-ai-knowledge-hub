# 面试技术要点（五方向考点映射）

> 这份文档帮你把"代码"翻译成"面试能讲清楚的话"。每个方向给出：**核心考点 + 可能被问到的问题 + 本项目对应的回答素材**。

---

## 方向一：RAG 开发

**核心考点**
- 文档切片（chunking）策略：按字符 / 句子 / 语义；chunk 大小与重叠（overlap）怎么选。
- 向量化与检索：TF-IDF vs 句向量；余弦相似度；召回率怎么评估。
- 答案生成：如何避免幻觉（必须引用原文）；Prompt 怎么写。
- 工程权衡：索引更新、增量建库、检索结果重排（rerank）。

**可能被问**
- "为什么不直接把整篇文档丢给大模型？" → 上下文长度限制 + 噪声 + 成本 + 易幻觉。
- "检索不准怎么办？" → 调 chunk 粒度、加 metadata 过滤、引入 rerank、混合检索（关键词+向量）。
- "怎么评估 RAG 效果？" → 召回用 recall@k；答案用 faithfulness / answer relevance（可提 RAGAS）。

**本项目素材**：`rag/chunker.py`（带 overlap 切片）、`rag/embedder.py`（TF-IDF 兜底 + 句向量可选）、`rag/llm.py`（答案必须引用原文，降低幻觉）。

## 方向二：Python 后端开发

**核心考点**
- Web 框架选型：FastAPI 的异步、类型提示、自动 OpenAPI 文档。
- 数据校验：Pydantic 模型。
- 工程结构：路由 / 服务 / 模型分层，依赖注入。
- 测试：pytest 写接口测试。
- 安全与性能（可扩展）：鉴权、限流、缓存、异步任务。

**可能被问**
- "FastAPI 和 Flask/Django 区别？" → 异步原生、类型驱动、自带文档、性能好。
- "怎么保证接口健壮性？" → Pydantic 校验入参、异常处理、单元测试覆盖。
- "如果请求量大怎么扩展？" → 多 worker（uvicorn）、加缓存、数据库/向量库外置、水平扩容 + 负载均衡。

**本项目素材**：`backend/app/` 的分层结构、`tests/test_api.py`、`Dockerfile` 容器化。

## 方向三：AI 应用开发

**核心考点**
- 把模型能力变成产品：UI/UX、加载态、错误兜底、结果可解释（引用来源）。
- 前后端联调：前端如何调用后端 API、数据结构约定。
- 快速原型工具：Streamlit 适合 demo；生产可换 React/Vue。

**可能被问**
- "你做的应用解决了什么痛点？" → 让非技术用户也能用自然语言查公司内部知识。
- "体验上做了哪些细节？" → 引用高亮、加载提示、空状态处理、可上传多格式。

**本项目素材**：`ai_app/app.py`（对话式界面，展示问题与引用来源）。

## 方向四：大模型训练

**核心考点**
- 微调 vs 推理 vs RAG 的边界：什么时候该微调，什么时候用 RAG。
- LoRA 原理：低秩分解，只训少量参数，显存友好、可插拔。
- 数据工程：SFT 数据格式（instruction/input/output）、清洗、配比。
- 训练流程： Trainer / 优化器 / 学习率 / 评估指标 / 过拟合识别。
- 推理部署：量化、vLLM、本地加载。

**可能被问**
- "为什么用 LoRA 而不是全参微调？" → 省显存、训练快、多任务可存多个 adapter、不易灾难性遗忘。
- "数据从哪里来、怎么处理？" → 本项目用人工构造的小样本 `sample.jsonl` 演示流程；真实场景需清洗与去重。
- "怎么判断训好了？" → 看 loss 曲线、在验证集上做生成样例评估、避免过拟合（train/val loss 差距）。

**本项目素材**：`llm_training/finetune_lora.py`、`configs/lora_config.yaml`、`data/sample.jsonl`、`inference.py`。

## 方向五：云运维

**核心考点**
- 容器化：Dockerfile 多阶段构建、镜像体积、层缓存。
- 编排：docker-compose / K8s，服务发现、健康检查。
- 反向代理：Nginx 做 HTTPS、负载均衡、静态资源。
- CI/CD：GitHub Actions 自动测试与发布，保证主分支可用。
- 可观测性：监控（Prometheus）、日志、告警。

**可能被问**
- "容器化解决了什么问题？" → 环境一致性、隔离、易扩展、易回滚。
- "CI 保证了什么？" → 每次提交自动跑 lint + test，避免把坏代码合进主分支。
- "线上怎么发现问题？" → 健康检查 + 监控指标（QPS、错误率、延迟）+ 日志聚合。

**本项目素材**：`deploy/docker-compose.yml`、`deploy/nginx/nginx.conf`、`deploy/.github/workflows/`、`deploy/monitoring/prometheus.yml`。
