# 架构设计（Architecture）

## 1. 总体架构

本系统采用**分层 + 模块化**架构，前端、后端、算法、训练、运维各自独立，通过清晰的接口协作。

```
┌─────────────────────────────────────────────────────────────┐
│                        用户 / 浏览器                          │
└───────────────┬───────────────────────────────┬─────────────┘
                │  HTTP (Streamlit UI)           │  HTTP (直接调用 API)
                ▼                                ▼
        ┌───────────────┐                ┌──────────────────┐
        │  ai_app       │                │   API 调用方      │
        │ (Streamlit)   │                └──────────────────┘
        └───────┬───────┘
                │  REST API (JSON)
                ▼
        ┌───────────────────────────────────────────────┐
        │            backend (FastAPI)                    │
        │  routes ──> services/rag_service ──> rag 模块   │
        │  config / schemas / 依赖注入                     │
        └───────────────┬───────────────────────────────┘
                        │  import
                        ▼
        ┌───────────────────────────────────────────────┐
        │         rag 模块（RAG 开发核心）                 │
        │  chunker → embedder → vector_store → retriever  │
        │  → llm(答案合成) → pipeline                     │
        └───────────────────────────────────────────────┘

  运维层：deploy/
    docker-compose 编排 backend + ai_app + nginx
    GitHub Actions 做 CI(测试) + CD(构建镜像)
    Prometheus 采集健康检查指标
```

## 2. 模块交互说明

### 数据流（问答）
1. 用户在 `ai_app` 或 API 提交问题。
2. `backend` 收到请求，调用 `rag_service.ask()`。
3. `rag_service` 调用 `rag.pipeline.query(question)`。
4. pipeline 内部：检索器返回相关 chunk → `llm` 合成答案（默认抽取式，引用原文）。
5. 结果层层返回，前端展示**答案 + 引用来源**。

### 数据流（建库）
1. 上传文档 → `backend` 保存到 `data/` → 调用 `pipeline.index(documents)`。
2. `chunker` 切片 → `embedder` 向量化 → `vector_store` 落内存索引。
3. 后续问答即可命中。

## 3. 关键设计决策

| 决策点 | 本项目做法 | 原因 |
| --- | --- | --- |
| 向量化 | 默认纯 Python TF-IDF | 零下载、零 GPU、演示稳定；接口预留句向量 |
| 向量存储 | 内存稀疏向量 | 小数据够用；预留 FAISS/Milvus 升级路径 |
| LLM | 默认抽取式合成 | 离线可跑、答案可溯源；预留 HuggingFace/OpenAI |
| 后端框架 | FastAPI | 异步、自动文档、类型安全 |
| 部署 | docker-compose | 一条命令起全套，面试当场可演示 |

## 4. 可扩展性（面试加分项）

- **换嵌入模型**：实现 `BaseEmbedder` 子类（如 `SentenceTransformerEmbedder`）即可。
- **换向量库**：`VectorStore` 接口可替换为 FAISS / Milvus / PostgreSQL(pgvector)。
- **换 LLM**：`BaseAnswerSynthesizer` 可接入本地大模型或云端 API，pipeline 无需改动。
- **加鉴权/限流**：在 `backend` 的路由层加依赖即可，不影响业务。
- **上云**：`deploy/` 的镜像与 compose 可直接部署到任意支持容器的云平台。
